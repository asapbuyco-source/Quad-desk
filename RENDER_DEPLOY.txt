  quant-desk-frontend   Static site (Vite build -> dist), free

SOURCE
  Repo:   https://github.com/asapbuyco-source/Quad-desk   (PUBLIC)
  Branch: claude        <-- all current work lives here (default is main)

BLUEPRINT
  render.yaml at the repo root defines both services, including:
    - backend: rootDir=backend, python 3.11.9, health check /health
    - frontend: static, npm ci && npm run build, publish ./dist,
      SPA rewrite /* -> /index.html, long cache for /assets/*
    - VITE_API_URL      <- backend RENDER_EXTERNAL_URL
    - VITE_BACKEND_API_KEY <- backend BACKEND_API_KEY (generated)
    - FRONTEND_URL      <- frontend RENDER_EXTERNAL_URL

--------------------------------------------------------------------------------
REGION / PLAN — IMPORTANT
--------------------------------------------------------------------------------
  Render's FREE web services run in Oregon (US) and sleep after 15 minutes.
  Binance blocks US IPs (HTTP 451), which breaks these backend endpoints:
      /cross-venue, /premium, /funding-heatmap, /oi-leaderboard, /heatmap,
      /backtest, /analyze/*
  Everything else (Marketaux news, FRED macro, Frankfurter FX) works from the US.

  Therefore the backend is configured as:
      plan: starter   ($7/mo)
      region: frankfurt (non-US, Binance allowed)

  If you must stay on the free plan, the Binance-backed panels will show
  errors but the rest of the site will work.

  NOTE: the frontend streams Binance market data directly from the browser,
  so live prices/trades/order flow work regardless of the backend region.

--------------------------------------------------------------------------------
HOW TO DEPLOY — OPTION A (dashboard, ~2 minutes)
--------------------------------------------------------------------------------
  1. Render Dashboard -> New + -> Blueprint
  2. Connect / paste: https://github.com/asapbuyco-source/Quad-desk
  3. Branch: claude
  4. Apply — Render creates both services from render.yaml
  5. Enter the secrets listed above when prompted
  6. Wait for the backend build (~3-5 min) and the static build (~2 min)

HOW TO DEPLOY — OPTION B (Render API, what the agent will do)
--------------------------------------------------------------------------------
  With a Render API key, the agent will:
    1. GET  /v1/owners                      -> owner id
    2. POST /v1/services                    -> create quant-desk-backend
    3. POST /v1/services                    -> create quant-desk-frontend
    4. PUT  /v1/services/{id}/env-vars      -> set secrets + cross-service URLs
    5. Trigger deploys and poll GET /v1/services/{id}/deploys
  Requirements for API creation: the repo is PUBLIC, so no GitHub app install
  is needed; branch is set explicitly to `claude`.

--------------------------------------------------------------------------------
POST-DEPLOY CHECKS
--------------------------------------------------------------------------------
  Backend:   https://<backend>.onrender.com/health          -> 200
  Backend:   https://<backend>.onrender.com/macro           -> needs X-API-Key
  Frontend:  https://<frontend>.onrender.com                -> 200
  CORS:      preflight from the frontend origin must return
             access-control-allow-origin: https://<frontend>.onrender.com

  If CORS fails, the cross-service URL link did not resolve on first build:
  set FRONTEND_URL on the backend to the static site URL manually and redeploy.
  If the frontend shows a blank page, set VITE_API_URL on the frontend to
  https://<backend>.onrender.com and redeploy (Vite bakes it at build time).

--------------------------------------------------------------------------------
DIFFERENCES vs RAILWAY
--------------------------------------------------------------------------------
  - Render has no local "upload" command; it always builds from Git. Because the
    repo is public, a direct public-repo deploy works without GitHub auth.
  - Static frontend is free and does not need a payment method.
  - Always-on backend/worker requires a paid instance; backend is set to starter.
  - The bot is intentionally excluded, so no worker service is needed.
