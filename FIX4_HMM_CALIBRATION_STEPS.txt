# Fix 4 — HMM Calibration (One-Time Setup)

## What This Fix Does

The bot uses a 3-state Hidden Markov Model (HMM) to classify market regimes
as RANGE, TREND, or VOLATILE. The emission parameters (_MU and _SIGMA arrays)
are currently hand-tuned placeholders that don't match BTC's actual statistical
distribution. This causes the HMM posterior probabilities to be unreliable,
leading to wrong regime classification and incorrect strategy activation.

Calibrating the HMM on 2 years of real BTCUSDT data fixes this.

---

## Prerequisites

Install the calibration dependencies (one-time):

    cd C:\Users\pc\Desktop\projects\Quad-desk
    pip install hmmlearn scikit-learn

---

## Step 1 — Run the Calibration Script

    cd C:\Users\pc\Desktop\projects\Quad-desk
    python -m bot.hmm_calibrate --symbol BTCUSDT --interval 15m --years 2

Expected runtime: 5-15 minutes depending on your internet speed.

The script will:
  - Fetch ~2 years of 15-minute BTCUSDT klines from Binance via CCXT
  - Fit a 3-state GaussianHMM using Baum-Welch expectation-maximization
  - Print the calibrated _MU and _SIGMA arrays to the terminal

Copy the output (it will look something like this):

    # Calibrated emission parameters:
    _MU = np.array([
        [0.00312, 0.78, 0.048, 0.21],
        [0.00685, 1.52, 0.312, 0.53],
        [0.01341, 2.48, 0.661, 0.84],
    ], dtype=float)

    _SIGMA = np.array([
        [0.00102, 0.39, 0.098, 0.103],
        [0.00287, 0.77, 0.248, 0.198],
        [0.00521, 0.99, 0.301, 0.152],
    ], dtype=float)

(Your numbers will be different — use YOUR output, not this example.)

---

## Step 2 — Locate the Placeholder Arrays in main.py

Open bot/main.py and search for:

    _MU = np.array([
        [0.003, 0.8, 0.05, 0.20],   # RANGE
        [0.007, 1.5, 0.30, 0.55],   # TREND
        [0.014, 2.5, 0.65, 0.85],   # VOLATILE
    ], dtype=float)

    _SIGMA = np.array([
        [0.0010, 0.40, 0.10, 0.10],
        [0.0030, 0.80, 0.25, 0.20],
        [0.0050, 1.00, 0.30, 0.15],
    ], dtype=float)

Replace BOTH arrays with your calibrated output. Delete the comments
(# RANGE, # TREND, # VOLATILE) — the new arrays won't have them.

---

## Step 3 — Enable Online Updates

In the same file, find _HMMRegimeClassifier.__init__() and change:

    self._online_update_enabled = False

To:

    self._online_update_enabled = True

This allows the HMM to continuously adapt its emission parameters to current
market conditions while keeping the calibrated baseline intact.

---

## Step 4 — Update update_every for Railway Efficiency

Find the HMM classifier instantiation and reduce update frequency to save CPU:

    _hmm_classifier = _HMMRegimeClassifier(window=60, update_every=500)

(Change update_every to 500 if it is currently lower, e.g. 50 or 100.
500 means the HMM re-estimits params every 500 cycles (~12.5 hours at 15s cycles),
which is safe and inexpensive.)

---

## Step 5 — Verify

    python -m py_compile bot/main.py

No output means success.

---

## Notes

- This is a ONE-TIME fix. After pasting your calibrated arrays, the bot will
  use them on every restart. Online updates will refine them continuously.
- If you re-run the calibration later (e.g., after a significant market regime
  shift like a new all-time high or a crash), repeat Steps 1-4 with new data.
- Run in dry-run mode for 48 hours before using real capital. Monitor the log
  for HMM committed_regime transitions — they should not flicker every cycle.
  A healthy transition rate is 1-3 per hour, not 10+.
