FIX-2: MAD adaptive window is computed but never used
--------------------------------------------------------------------------------
File:        bot/quant_engine.py
Location:    _lob_metrics() — Stage 2 MAD Persistence Filter (lines ~845-848)
Current bug: The adaptive window is computed and stored in self._mad_window, but 
             the outlier detection code at line ~789 uses the FULL deque:
                 arr = np.array(self._ofi_history)
             It never slices to the adaptive window. The floor of 32 is therefore 
             never enforced.

Current code (line ~845-848):
    atr_rank = min(max(getattr(self, '_atr_pct_rank', 0.5), 0.1), 1.0)
    target_window = max(32, min(100, round(100 * (1 - atr_rank ** 0.80))))
    self._mad_window = int(0.70 * getattr(self, '_mad_window', 32) + 0.30 * target_window)

Current code (line ~789, outlier detection):
    if len(self._ofi_history) >= 20:
        arr = np.array(self._ofi_history)
        median_ofi = float(np.median(arr))
        mad = float(np.median(np.abs(arr - median_ofi)))

Required change:
    # In __init__ of QuantEngine, add:
    self._mad_window = 32

    # In _lob_metrics(), replace the outlier detection block:
    window = max(20, getattr(self, '_mad_window', 32))
    if len(self._ofi_history) >= window:
        arr = np.array(list(self._ofi_history)[-window:])
        median_ofi = float(np.median(arr))
        mad = float(np.median(np.abs(arr - median_ofi)))

FIX-5: Z-drift filter is applied BEFORE strategy selection (double-counting)
--------------------------------------------------------------------------------
File:        bot/main.py
Location:    _compute_signal() — VOLATILE regime block (lines ~2533-2540)
Current bug: The Z-drift gate is placed BEFORE _strategy_trend() is called. 
             This means the filter blocks even when the strategy would reject 
             the entry anyway, causing "z_drift_blocked" to count false positives.
             The plan says the filter should run "before strategy/risk gates 
             FINALIZE an entry" — i.e., AFTER the strategy has selected a direction 
             but BEFORE the confidence threshold and risk engine finalize it.

Current code (lines ~2533-2540):
    elif regime == "VOLATILE":
        z_current = metrics.get("zScore", 0.0)
        vol_z_thr = regime_p.get("z_threshold", 1.75)
        
        # Z-Drift Entry Pre-Filter
        if abs(z_current) < 0.75 * vol_z_thr:
            BOT_STATS["gate_stats"]["z_drift_blocked"] = BOT_STATS["gate_stats"].get("z_drift_blocked", 0) + 1
            return {**WAIT, "analysis": f"Z-drift blocked: abs(z) {abs(z_current):.2f} < 0.75 * {vol_z_thr}"}
        
        strategy_type = "TREND"
        raw_direction = _strategy_trend(metrics, z_min=vol_z_thr)

Required change:
    Move the Z-drift gate to AFTER raw_direction is determined but BEFORE 
    the confidence threshold check (around line 2543, after the strategy block).
    
    # If no strategy direction, no point checking Z-drift
    if raw_direction is None:
        _gate_stats_summary("signal_none")
        return {**WAIT, "analysis": f"Regime={regime} strategy={strategy_type} — no edge."}
    
    # Z-Drift Pre-Filter (only applies when a strategy direction exists)
    if regime == "VOLATILE":
        z_current = metrics.get("zScore", 0.0)
        vol_z_thr = regime_p.get("z_threshold", 1.75)
        if abs(z_current) < 0.75 * vol_z_thr:
            BOT_STATS["gate_stats"]["z_drift_blocked"] = BOT_STATS["gate_stats"].get("z_drift_blocked", 0) + 1
            logger.info(f"[ZDrift] Blocked {raw_direction} — abs(z) {abs(z_current):.2f} < 0.75 * {vol_z_thr}")
            return {**WAIT, "analysis": f"Z-drift blocked: abs(z) {abs(z_current):.2f} < 0.75 * {vol_z_thr}"}
